# 滑铲（Slide）

> 功能：地面上跑动时按 **L**，人物朝输入方向滑铲冲出去；滑铲中按跳跃键可以做**滑铲跳**，
> 保留冲刺速度起跳。

本文记录**做了什么、为什么这样做、以及怎么调参**。

相关文档：[扒墙 / 蹬墙跳](wall-slide-jump.md) —— 两者共用一套「横向速度接管」的思路。

## 二、触发条件

按 **L**（新增的独立按键），必须**同时**满足：

| # | 条件 | 代码 |
|---|---|---|
| 1 | 在地面上 | `phyCheck.isGround` |
| 2 | **正在跑动** | `Mathf.Abs(inputDirection.x) > 0.1f` |
| 3 | 不在滑铲中 | `!isSliding` |
| 4 | 不在扒墙中 | `!isWallSliding` |
| 5 | 未受伤、未死亡 | `!isWounded && !isDead` |

**方向由输入方向决定** —— 按住 `←` 再按 `L` 就是向左滑铲，人物同时转向该方向。

> **为什么要求「正在跑动」**：按住方向键本身就进跑步动画，在跑动中滑铲比原地按 L 更符合直觉。
> 想放宽成「原地也能滑铲」，把条件 2 那行去掉即可（方向改为用 `transform.localScale.x`）。

### 结束条件（进入 End 阶段）

| 触发 | 说明 |
|---|---|
| 时长达 | `slideDuration` 用完 |
| **离开地面** | 滑出平台直接收招，不做空中滑铲 |
| 受伤 / 死亡 | 强制打断 |

> 滑出平台后不用特殊处理：`ANY -> Jump [isGround=IfNot, isWallSlide=IfNot]` 会自动接管，
> 直接切到下落动画。

## 三、参数（Inspector 可调）

挂在玩家身上 `PlayerController` 的 **「滑铲」** 分组：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `slideSpeed` | **9** | 滑铲水平速度。`speed` 是 6，所以快了 50%，有冲刺感 |
| `slideDuration` | **0.5** | 滑铲主体时长（Start 播完之后还能滑多久） |

### 时长是怎么凑出来的

```
Start  3 帧 @ 10fps = 0.3s   （靠 Exit Time 自动切 Loop）
Loop   3 帧 @ 10fps = 0.3s   （循环，持续 slideDuration = 0.5s）
End    2 帧 @ 10fps = 0.2s   （靠 Exit Time 自动回 Idle）

整套动作 ≈ 0.3 + 0.5 + 0.2 = 1.0 秒
```

## 五、🔴 三个必须知道的坑

### 坑 1：`PlayerInputCtrl.cs` 是自动生成的，不能手改

```
Assets/Settings/Input System/PlayerInputCtrl.inputactions   ← 源资产（改这个）
Assets/Settings/Input System/PlayerInputCtrl.cs             ← 自动生成（别碰）
```

`.cs` 头部写着：

```csharp
// <auto-generated>
//     Changes to this file may cause incorrect behavior and will be lost if the code is regenerated.
```

**正确改法**：改 `.inputactions`，然后重新导入触发 `InputActionCodeGenerator` 重新生成 `.cs`。

> ⚠️ **实测踩到的坑**：用 Input System 的 `InputActionSetupExtensions.AddAction()` 改完，
> 调 `EditorUtility.SetDirty()` + `AssetDatabase.SaveAssets()` **不会写盘** ——
> `git status` 干净、重新加载资产后动作消失。
>
> **可行做法**是直接写文件：
> ```csharp
> System.IO.File.WriteAllText(path, asset.ToJson());
> AssetDatabase.ImportAsset(path, ImportAssetOptions.ForceUpdate);
> ```
> 之后确认生成的 `.cs` 里出现 `public InputAction @Slide` 才说明真的生效了。

### 坑 2：`move()` 每帧无条件覆写 `velocity.x` → 滑铲必须接管

```csharp
// PlayerController.move()
rb.velocity = new Vector2(inputDirection.x * speed, rb.velocity.y);   // ← 无条件覆写
```

滑铲时如果落到 `move()` 手里，你设的 `slideSpeed = 9` 下一帧就被换成 `speed = 6`（甚至 0）。

所以 `FixedUpdate()` 里滑铲分支**直接 return**，根本不调 `move()`：

```csharp
if (isSliding)
{
    rb.velocity = new Vector2(slideDir * slideSpeed, rb.velocity.y);
    return;
}
```

> 这**和蹬墙跳是同一个坑**（见 wall-slide-jump.md 的「坑 1」）。

### 坑 3：滑铲跳也要锁定横向输入

滑铲跳如果只是 `AddForce` 起跳，横向速度下一帧就会被 `move()` 抹成 `speed`(6)，冲刺感全没了。

所以 **复用**蹬墙跳那套 `wallJumpLockTimer`：

```csharp
private void SlideJump()
{
    isSliding         = false;
    wallJumpLockTimer = wallJumpLockTime;                      // 复用同一个横向锁定
    rb.velocity = new Vector2(slideDir * slideSpeed, jumpForce);   // 直接赋值，不用 AddForce
}
```

`wallJumpLockTimer` / `wallJumpLockTime` 现在是**蹬墙跳和滑铲跳共用**的「横向输入锁定」——
它的 Tooltip 还写着「蹬墙后…」，语义已经扩大，但**刻意没有改名**：
改名会让场景里已序列化的 `wallJumpLockTime: 0.2` 失效（Unity 按字段名反序列化）。

## 六、Animator 结构

### 参数

```
velocityX(Float)  velocityY(Float)  isGround(Bool)
wounded(Trigger)  isDead(Bool)      isAttack(Bool)  attack(Trigger)
isWallSlide(Bool)  isSliding(Bool)   ← 本次新增 isSliding
```

状态判定全在 `PlayerController.Slide()` / `UpdateSlide()` 里完成，
`PlayerAnimation` 只负责把结果喂给 Animator —— **不在 Animator 里做物理判断**。

### Base Layer 新增部分

```
SlideStart (3帧, 不循环) ──[Exit Time]────────────▶ SlideLoop
SlideLoop  (3帧, 循环)   ──[isSliding = false]───▶ SlideEnd
SlideEnd   (2帧, 不循环) ──[Exit Time]───────────▶ BlueIdle

进入滑铲（只从"地面"状态进）：
  BlueIdle  ──[isSliding = true]──▶ SlideStart
  BlueRun   ──[isSliding = true]──▶ SlideStart
  BlueLand  ──[isSliding = true]──▶ SlideStart
  SlideEnd  ──[isSliding = true]──▶ SlideStart   （允许紧接着再滑一次）
```

**为什么 Start→Loop 和 End→Idle 用 Exit Time 而不是代码控制阶段**：
这样「最短滑铲时长」天然等于 Start 的 0.3 秒，
代码只需要维护**一个 `isSliding` bool**，不用再传「当前是第几阶段」。

✅ **不用像扒墙那样给 `ANY -> Jump` 打补丁** —— 滑铲时 `isGround == true`，
而那条转场要求 `isGround = IfNot`，天然互斥。

## 七、交互规则

| 行为 | 是否允许 | 实现 |
|---|---|---|
| **跳跃** | ✅ | 变成**滑铲跳**：保留水平速度 + 垂直起跳 |
| **攻击** | ❌ | `PlayerAttack()` 里 `if (isSliding) return;` |
| **受伤** | 打断 | `UpdateSlide()` 检查 `isWounded` |
| **离开地面** | 结束 | `UpdateSlide()` 检查 `!isGround` |
| **扒墙** | 互斥 | 滑铲要求 `isGround`，扒墙要求 `!isGround` |

> **为什么滑铲时禁止攻击**：Attack Layer 是 `weight=1 / Override / 无 Avatar Mask` 的**全身层**，
> 一进攻击状态就会把滑铲动画整个盖掉。这与扒墙时禁止攻击是同一个原因
> （详见 wall-slide-jump.md 的「坑 4」）。

## 八、连招

```
地面滑铲 ──[L]──▶ 滑铲跳 ──[空格]──▶ 空中撞墙扒住 ──[空格]──▶ 蹬墙跳
```

三个机制共享同一套「横向速度接管 + 输入锁定」的思路，所以能自然衔接。

## 九、调参指南

> ⚠️ **改完 Inspector 里的参数，必须 `Ctrl+S` 保存场景，再按 Play。**
> 本项目的场景是 Addressables 加载的，加载的是磁盘上已保存的场景 ——
> 不保存的话运行时实例拿到的还是旧值。详见 wall-slide-jump.md 第七节。

| 想要的效果 | 怎么调 |
|---|---|
| 滑得更快 / 更慢 | 调 `slideSpeed`（当前 9，`speed` 是 6） |
| 滑得更久 / 更短 | 调 `slideDuration`（当前 0.5s） |
| 原地也能滑铲 | 删掉 `Slide()` 里的 `Mathf.Abs(inputDirection.x) <= 0.1f` 判断 |
| 滑铲跳冲得更远 | 调大 `wallJumpLockTime`（与蹬墙跳共用） |
| 滑铲动画节奏 | 改 3 个 clip 的 `frameRate`（当前 10，即 guide 建议的 100ms/帧） |
| 加滑铲冷却 | 目前**没有冷却**，可以连续滑。需要的话加一个 `slideCooldown` 计时器 |

## 十、已知限制 / 待实测

1. **碰撞体没有变矮** —— 本次是纯视觉滑铲，**钻不了矮通道**。
   真要做「滑铲过矮通道」，需要滑铲期间换矮版 `CapsuleCollider2D`，
   并处理「站起来时头顶有东西」的经典问题（卡住 / 强制保持蹲姿）。
2. **没有冷却** —— 只要满足触发条件就能一直滑。
3. **没有滑铲音效** —— 跳跃和蹬墙跳都会调 `AudioDefination.PlayAudioClip()`，滑铲没加，
   因为那会复用跳跃的音效。需要的话得先给 `AudioDefination` 加一个独立的滑铲音。
4. **L 键没有手柄绑定** —— 与 `Jump` / `Attack` 保持一致（它们也只有键盘绑定）。
